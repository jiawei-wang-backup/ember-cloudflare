# Ember 业务总览与反馈落实

这轮将六项目的入口组织为“项目总览、项目讨论、反馈与落实”，让业务协作者先了解项目，再按需查看技术依据。
监控服务继续只读原来明确配置的六项目；所有反馈与演示写入独立中文 Ember。Fernwood 不启用这些入口，普通房间也不会初始化工作流表。

## 产品思路

1. **先回答业务问题。** 总览先说明为什么做、服务谁、要完成什么流程，再展示已有能力、当前卡点及可以提供的协助。
2. **用模块组织工作。** 将原始阶段记录映射到业务模块，模块内保留里程碑、证据和原始事项名称。新出现而未映射的记录保留在“其他阶段记录”，不静默丢弃。
3. **完成与可用分开。** 历史开发、测试或发布记录只证明对应范围。当前入口是否可用、业务是否接受仍需确认，尤其不能把阻塞项目的历史成果当成已恢复。
4. **让协作者能行动。** 业务同事可以直接对模块或里程碑提反馈；讨论消息的“…”提供单条采纳、多选采纳。多条讨论合成一项落实事项，避免把每一句话都变成任务。
5. **按需展开信息。** 项目背景和模块在总览页，落实流程在独立页签，统计放在弹出面板，讨论筛选放在弹层。聊天首屏不叠加几块展开面板。
6. **以证据关闭反馈。** 采纳后明确执行人和验收条件，执行者提交产出，负责人核查后验收。状态更新回传讨论，并可打开同一条落实记录；有问题可以受阻、退回或重新打开。

模块之上另有“哪些模块合起来，才算完成一次可用交付”：例如变声器的首装到开播、升级到回退，串联多个模块的阶段记录和验收条件。即使关联记录全部完成，也只显示待业务验收，不能由记录比例自动认定业务可用。

## 六个项目的业务模块

|项目|模块|
|---|---|
|project-pulse|开发活动自动归集、项目进展与产出查看、当前开发活动识别|
|jxaccount|多公司员工登录、组织目录与业务访问、应用凭证维护|
|mfa-approval|申请到验证码投递、登录邮件识别与提取、交付版本确认|
|wzwx-score|赛事报名与组织、赛果核对与成绩交付、赛局采集与资料服务、手机与无障碍体验|
|deltaforce-game-library|可追溯资料与查询、图片与三维资料浏览、战绩查看与更新、迁移后恢复使用|
|xiaoxing-voice-changer|首装与开播配置、直播变声效果与稳定性、在线更新与回退|

这些名称与业务说明是依据已有项目目标、阶段摘要整理的业务视图。未宣称已经读取全部原始 PRD、远程手册全文或 PR diff。
每个里程碑同时保留源标题与证据，来源日期及断连快照状态可见。未确定的交付日期不由 Token 数、PR 数或阶段百分比预测。
个人 Codex 的实时代理尚未连接，不以虚拟成员回复冒充本机真实上下文；已有项目助手与原生 AI 工具会得到业务模块信息。

## 反馈状态与权限

`待评估 → 已采纳 → 落实中 → 待验收 → 已验收`

落实中可以记录受阻，再恢复落实；待验收或已验收可以退回落实。待评估或已采纳可以暂不采纳，暂不采纳的事项可重新评估。

- 频道成员可提反馈、补充信息及查看记录。
- 项目管理员／频道创建人可采纳、分派、调整安排、暂不采纳、验收和重新打开。
- 执行人可开始落实、记录卡点及提交产出；负责人也可以执行这些操作。
- 采纳／分派要求执行人和验收条件，开始落实前也检查；约定日期可留空。
- 提交验收要求至少一条 PR、产出文档或验证记录链接，验收要求明确的检查说明。
- 负责人作出的本地反馈验收，不会修改远端监控项目的里程碑或完成率。演示流程始终带标识。

## 存储与追溯

工作流有独立的结构化记录和事件表，聊天正文不是状态的唯一依据。
每次更新校验版本，状态更新与事件插入使用同一批事务；请求编号保证重试去重，历史按版本排序。
状态回传使用同一请求编号作为原生消息的去重依据，数据库更新后回传中断时，重试可补齐消息。
原始讨论和采纳方案保留链接，Thread 回复链接指向原 Thread；原文被删除时明确显示不可用。
界面允许修改期间保持原版本基准，避免后台刷新后悄悄覆盖别人的变更。

`0063_project_feedback.sql` 属于按需初始化的 `project` 范围，只在授权项目工作流请求中打开。
DO SQLite 的普通房间不执行此范围；D1 使用同一迁移清单，每条查询都限定 room_id。
已有聊天、交付卡片与旧采纳方案保留；旧方案可通过消息采纳入口纳入落实。

## 验证与体验

后续性能排查与界面精简见[性能排查记录](./performance-investigation.md)：已完成两种存储和前端完整 quick，原四项回退未再触发阈值。下方性能段落保留本轮业务改造当时的采样背景。

使用中文管理员登录后，默认打开业务总览。也可在讨论中从“…”选择“采纳此条”或“加入多选采纳”，确认业务模块并生成方案，随后进入落实工作台补充安排。
六项目中提供 12 条明确标注的流程演示，覆盖待评估、已采纳、落实中、受阻、待验收和已验收。
已验收样例仅验证本地来源附件、核对单和操作记录，不冒充原产品的真实验收结论。

局域网真实浏览器验证了六项目总览、刷新持久化、管理员分派、成员开始／受阻／恢复／提交产出、管理员验收，以及更新消息返回同一反馈。消息菜单单条采纳、多选采纳、统计弹窗、筛选弹层和 390px 手机布局均通过；未出现页面错误或横向溢出。
原有 147 张项目卡片、147 张汇总卡片、48 个 Thread 和来源附件保留，原生数据校验通过；原 Fernwood 的 14 个 SQLite 数据文件未出现本次反馈表。

中文局域网启动器直接提供构建后的公开静态资源，减少本地开发代理的资源转发中断；API、聊天 WebSocket、头像及私有文件仍经 Worker。只允许构建目录内白名单路径，局域网不能访问本机工具和身份检查入口。

本轮相关前端测试 115 项、最近一次 Worker 业务与反馈测试 12 项通过，另有前面的 Worker 回归 58 项；全仓类型检查、生产前端构建和中文脚本类型检查通过。完整 quick 性能运行未完成；完成的 SQLite 延迟／历史快速测试未丢消息，但相对前次结果的四项延迟指标超出阈值（ack p50 5.5→14.48ms、delivery p50 5.4→14.21ms、welcome p50 3.79→33.35ms、page p50 1.08→10.06ms）。采样时主机有其他高负载任务，尚不能确定原因，也不能宣称性能回归检查通过。结果保存在忽略提交的 `.wrangler/demo-cn/perf-meeting-focused/`，需要在可比负载下补测定位。
