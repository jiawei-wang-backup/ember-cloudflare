## 启动与初始化

在项目根目录执行（Node 22.22.2+ / 24.15+ / 26+，仓库锁定 pnpm 10.18.3）：

```sh
corepack pnpm install --frozen-lockfile
corepack pnpm build
corepack pnpm dev:demo-cn
```

保持该终端运行，在另一个终端初始化：

```sh
corepack pnpm seed:demo-cn
```

打开 <http://localhost:5174>。工作空间为 **Project Pulse · 研发协作中心**。
演示定位：团队项目研发、技术讨论、问题跟踪、版本交付和 AI 协作工作空间。
Ember 的副标题最多 30 字，因此侧栏使用较短的副标题；完整背景见公告和需求附件。

`pnpm` 已使用正确版本时，可直接运行 `pnpm dev:demo-cn`、`pnpm seed:demo-cn`。
前端使用本地构建产物；修改网页源码后需重新构建。Ctrl+C 停止中文启动命令，不会停止英文服务。

|中文 Project Pulse|http://localhost:5174|8790|.wrangler/demo-cn/state|

中文 Worker 固定使用 `--local`、回环监听和 `ember-demo-cn` 名称。`dev:demo-cn` 的 5174 为回环入口；`dev:lan` 将应用代理开放给局域网，内部 Worker 仍只在回环监听。5174 是中文演示的
HTTP/WebSocket 转发入口，同时提供环境身份检查。8790 已占用时拒绝启动。种子脚本不接受目标地址，
先验证 5174 的专用身份响应；不能拿它对生产 Cloudflare 或 5173 写数据。
原 `pnpm dev`、`pnpm seed`、英文人物和对话内容均保留。共用 seed client 仅补充 TypeScript 类型标注，运行行为不变。

重复执行 `seed:demo-cn` 发现已初始化时直接友好跳过，不重复插入。`manifest.json` 的 `status: complete`
表示完整导入；初始化中断时也会拒绝继续追加，凭证提前保存以便排查。没有自动清空/重置命令。
确需重建时，先停止中文服务，把**仅 `.wrangler/demo-cn` 这个目录**移到新的备份目录，再启动和初始化。
保留备份可恢复原中文数据；不要操作 `apps/worker/.wrangler/state`。本次试运行的未完成中文环境已单独保存在
`.wrangler/demo-cn-incomplete-backup-20261116`，未清空任何英文数据。

## Bot 测试

管理员在 Admin 的 Chat bots 页面可查看 **GitHub Bot · 演示** 及交付频道的原生 Slack Webhook 地址。
可复制该**本地**地址，按下面格式发送一条新通知；不需要配置真实 GitHub：

```sh
curl -X POST '这里替换为中文环境交付频道的本地 Slack Webhook URL' \
  -H 'Content-Type: application/json' \
  -d '{"text":"【演示数据】现场 Webhook 连通测试","blocks":[{"type":"section","text":{"type":"mrkdwn","text":"*本地 Webhook 测试*\n状态：消息接收成功\n这是模拟通知，不代表 CI 或验收完成。"}}]}'
```

保持频道打开，可看到卡片实时到达。Webhook 中的 key 属于本地凭证，不要提交到仓库。
GitHub 卡片的 URL 校验拒绝 `localhost` 链接按钮，正文中的原讨论链接仍可使用。
另新增 **协作演示助手**，通过 Ember 原生 `action_id` 按钮和真实本地回调实现交互，不依赖 URL 按钮，也没有绕过校验：

1. 打开“交付与验收”或“技术讨论”最下方的“可交互的交付说明”。
2. 点击“查看验收清单”，原卡片会更新，显示检查清单及点击人的姓名。
3. 点击“查看项目边界”，卡片切回六项目当前阶段。可反复点击，产生真实编辑标记，不新增一串通知。
4. 在“技术讨论”中 @协作演示助手，会收到规则式说明，明确标注“非 AI”。这是真实 Bot webhook 回复，不是假装模型生成。

该 Bot 只切换说明，不执行审批、部署、CI 或验收。回调只在 5174 的回环开发服务存在；随机 token 存在
忽略提交的 `.wrangler/demo-cn/callback-token`（0600），不会写到正式 Worker 配置。错误 token/方法返回 404，
损坏 JSON 返回 400，未知按钮返回 422。没有连接真实 GitHub，也没有新增生产通知系统。

## 增强版现场演示路线与功能覆盖

建议先用顾远账号登录一个浏览器配置文件，再用林屿或梁沐账号登录另一个。顺序如下：

1. **团队与成员**：看新的人物头像、不同频道图标；点击成员头像查看中文简介。管理员进入成员管理可展示角色界面，不必实际封禁或删除成员。
2. **实时协作**：两个窗口打开同一频道，一个窗口输入，另一个观察在线成员与输入指示；发送消息后观察实时到达。切换频道查看未读与 Activity，再用 @成员产生一条明确的提及。
3. **富文本和编辑**：每个项目底部有“本轮协作演示”消息，包含粗体、强调、列表、划线、成员提及和真实编辑标记。点引用、添加 emoji 或文字回应，现场补一条代码块。
4. **Thread 附件**：打开该消息的 Thread，里面有实际上传的项目验收 JSON 清单。可展开、下载、继续回复，并切换“Also send to”演示回复同时发送到频道。
5. **交付 Bot**：看每个项目的三张卡片，再去交付汇总频道看完整研发事件流；点击协作演示助手的两个按钮，观察真实回调更新原卡片。@机器人展示规则回复。
6. **富媒体与链接**：智能剪辑频道播放视频；组件库下载/打开 PDF 和图片；研发日常查看日出图片和开源仓库资料预览。预览描述是人工整理，不冒充实时抓取。
7. **搜索与权限**：搜 `revision`、`Token`、`PR128`，从结果回到上下文；搜索界面可叠加频道、作者、文件、链接或 Thread 筛选。用周宁确认两个私人频道不可见，再切到已有私聊/多人私聊。
8. **个人体验**：收藏项目频道并拖动排序，打开频道通知设置，切换所有消息/仅提及。个人资料可显示登录二维码；二维码属于登录凭证，现场用自己的设备展示即可，不要放进公开演示截图。原生主题/外观设置、窄屏布局和键盘快捷键可以现场操作。
