## 项目协作入口

业务总览与反馈落实的最新界面、权限和验收说明见[业务协作设计](./business-collaboration-design.md)。六项目默认打开“项目总览”，另外两个页签为“项目讨论”“反馈与落实”；统计在弹窗中查看，消息筛选在弹层中设置，避免占满聊天高度。
断连加载、卡片展开性能与小字精简的后续结果见[性能排查记录](./performance-investigation.md)。

六个项目在侧栏及顶部显示阶段进度条，百分比来自“记录完成数 / 阶段总数”，不代表业务验收。
顶部人数区分人和 Bot，按当前 Ember 频道的实际成员统计；没有把监控参与者数量当成群人数，
也没有宣称已经同步飞书群成员。将鼠标移到人数上可看成员名单。
“项目总览”按六项目的业务目标展示背景、可用能力、卡点、跨模块交付流程及模块里程碑，详细证据按需展开。
中文环境的消息使用稳定的发言人配色，姓名和头像继续保留；英文环境不启用。

项目助手摘要新增“本次调用”与“项目用量”。结构化 Bot 不调用模型，本次输入、输出 Token 和
模型费用均为 0；项目统计另从监控读取，缺失时显示未知，不按字符估算或编造费用。
旧结构化查询回复也会显示这项调用说明。

“筛选消息”可组合只看 Bot、只看自己、指定发言人与开始／结束日期；日期按浏览器本地时区，
包含结束当天。筛选读取原生持久化频道历史，每次检查 100 条，并提供继续查看更早历史的入口，
不会把当前加载的几十条冒充全部历史。主频道历史不包含未同时发回频道的 Thread 回复，
Thread 仍可打开查看与选择采纳。“清除筛选”回到实时聊天。

项目管理员及频道创建人可选择 1 至 20 条讨论，填写说明后“确认采纳并发布方案”。
方案结合项目背景、阶段待办和原文节选，作为可搜索的原生消息保存，保留采纳人、原话链接、
依据时间、验证步骤和验收条件；在“采纳方案”中可筛选查看生成记录，也可进入“反馈与落实”补充执行人、验收条件与产出证据。方案生成不等于完成落实或已验收。
重复提交同一请求不会重复发布。普通成员可读方案，不能调用采纳接口；采纳前后均检查整个私人频道的项目授权。
配置可用 Ember AI 且其加入项目频道后调用现有模型生成方案；当前没有可用 LLM 时整理结构化清单，
明确标识生成方式，既不冒充 AI 推理，也不自动改动真实代码、监控数据或项目完成率。
模型模式当前未接入逐次 usage，Token 和费用显示未知，不用项目累计用量替代单次消耗。

## 监控断连时的展示

当前局域网监控服务不可达时，中文启动器加载同一正确来源的六项目核验快照，

快照只在服务端按已授权项目返回；验证来源 URL、项目标识和日期，不回退旧数据库。
已导入快照未保存 Token 统计，因此断连期间 Token 显示未知。
此快照配置仅写入忽略提交的中文 `pulse.wrangler.json`，不改变 Fernwood 的配置或存储。

本轮验证：前端相关 191 项、Worker 两种存储后端 26 项、协议 2 项测试通过，
全仓类型检查、中文脚本类型检查与构建通过。局域网真实浏览器验证六个项目、人数与 Bot 数量、
发言人配色、筛选、双消息采纳、刷新后保留方案及 390px 手机布局，无页面错误或横向溢出。
原生项目助手的新查询已验证单次 0 Token、项目用量未知及快照日期的区别。
原有项目卡片、来源附件、九人侧栏、私聊去重与 Fernwood 入口复查通过。

完整 quick 性能测试结果在 `.wrangler/demo-cn/perf-collab-after/`：两种存储后端与页面渲染未丢消息，
页面渲染无长任务。与本轮改动前保存的 `perf-ui-web-final` 前端结果比较，未触发性能回退阈值；
快速 Lighthouse 为单次采样，不据此宣称稳定提速。首次完整前测中断，故没有有效的后端前后性能比较。

## 顶部统计与项目助手

六个项目频道顶部默认只显示一行项目概览、状态、负责人摘要和展开入口。
负责人按用户约定直接显示面板的参与成员；多人全部保留，并合并同一成员在不同关联仓库的重复记录。
界面隐藏姓名末尾的设备标识，悬停仍可查看完整原始名称；此为展示规则，不向远程监控服务写入人员分配。
展开后先展示负责人、时间窗及四张关键指标卡片（输入、输出、待处理 PR、阶段记录），
其下以“阶段证据／产出文档／成员与活动／统计口径”标签页查看详情。
来源地址、未知字段与详细口径收在“统计口径”中，点击“收起统计”恢复一行。
Token 用“万／亿”缩写，悬停或聚焦数字可读取完整整数；未知值仍显示未知。
展开后的指标、时间窗和标签栏保持可见，只有详情面板滚动，手机端进一步压缩留白以保留聊天空间。
可切换近 1／7／30 天或点击刷新，刷新不改变展开状态；切换频道后默认收起。

所有查询统一经过 Ember 的 `/api/rooms/:roomId/project`，验证登录、频道成员资格和显式项目授权，
服务端再从 `192.168.16.70:4185/api/v1/dashboard` 按完整项目标识筛选；前端与助手拿不到全局 Dashboard。
允许的局域网 HTTP 地址只在中文私有配置里指定，不接受客户端传入其他项目或源地址。
失败时显示错误，不回退到旧库；旧的 4186 查询服务已停止。

这里沿用源服务 UTC+8 自然日口径：Token、活动受时间窗约束，PR、成员关系和阶段摘要是面板当前存量。
业务项目可包含显式列出的子仓库，例如 jxaccount 的 Token 按其关联仓库汇总，PR 保留真实仓库名称和链接。
两个未注册 UUID 的工作区直接按完整工作区标识查询，无需伪造 UUID。
源接口未提供可靠项目级 Cached、模型分布、成员用量、用量更新时间、项目费用或额度，显示未知。
不从全局模型数据分摊，不把无用量记录显示为零，不把阶段记录完成显示为已验收。

六个频道均已加入原生 **项目助手**，可以直接 @它询问：

- “请给本项目进度周报，包含近7天 Token、成员、PR产出和待验事项。”
- “今天 Token 用量是多少？”
- “近30天有什么产出文档？”（会说明 PR 是当前存量，并非该时间窗新增量。）

助手的回复标注“结构化查询模式，非 LLM 分析”，包含项目身份、证据来源与查询时间。
发到频道前另校验所有频道读者均有项目授权。新加入成员需要显式授权，不自动扩大数据访问范围。
Ember 原生 AI 的八个项目查询工具也共用同一服务端数据链路；当前仍未配置付费模型，不冒称已运行 LLM 推理。
