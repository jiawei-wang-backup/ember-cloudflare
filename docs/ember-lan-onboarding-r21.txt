執行順序：
1. 先讀 VERSION、README.md、UPGRADE.md、project-selection.md 和 SHA256SUMS，確認版本為 3.6.0/r21，並逐檔驗證 SHA-256。不要執行 PROMPT.txt 中會建立或接入專案的流程。
2. 檢查 Python 3、Codex CLI 登入狀態和瀏覽器。只報告是否可用，不輸出憑證內容。
3. 以短逾時只讀檢查三個服務根頁面，以及 Project Pulse 的 `/api/v1/report-directory`。執行 `python3 pulse-onboard.py links` 核對包內位址；任何位址與上面不一致時停止並報告。
4. 如果 HTTPS 憑證不受信任，向使用者說明根憑證是包內的 `Ember-LAN-CA.pem`。在包目錄執行下列命令核對公開根憑證：
   `openssl x509 -in ./Ember-LAN-CA.pem -noout -fingerprint -sha256`
   輸出中等號後的 SHA-256 指紋必須是：
   CA:51:9A:49:A2:90:1D:6B:90:42:B4:65:F2:FD:45:9F:37:5E:5A:57:EC:21:7F:C7:C1:84:AA:4D:5E:B0:91:4C
   macOS 可在包目錄執行：
   `sudo security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain ./Ember-LAN-CA.pem`
   撤銷時執行：
   `sudo security remove-trusted-cert -d ./Ember-LAN-CA.pem`
   只有核對指紋一致後才匯入；不要搬移或保存伺服器私鑰。
5. 開啟 http://192.168.16.70:5174，請使用者從上表選擇本人登入名登入。只填登入名，不填電子郵件；不要索取或記錄密碼。
6. 依套件流程發起 Ember HTTPS 網頁授權，讓使用者親自確認讀取頻道、存取專案頻道與傳送訊息權限。授權完成後只做唯讀工具探測，確認能列出頻道；不要傳送測試訊息。
7. 檢查 Codex CLI 是否已經登入。GitHub CLI 未登入不影響空資料接入；不要索取或傳送任何 GitHub 憑證。
8. 最後複查本機沒有生成專案選擇、上報批次、同步工作或代答監聽。不要為了讓檢查通過而建立空檔案、頻道或訊息。
